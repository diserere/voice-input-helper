# Требования пользователя — Voice Input Helper

Версия: v1 (первая итерация).

## 1. Цель и назначение

Расширение GNOME Shell для **быстрого голосового ввода текста** с использованием системного распознавания речи **Myna** (Ubuntu Speech-to-Text). Пользователь надиктовывает текст, и он попадает в буфер обмена — минимальное количество действий между «хочу сказать» и «текст вставлен в приложение».

## 2. Пользовательская персона

Пользователь Ubuntu GNOME (GNOME Shell 48–50), который **диктует чаще, чем печатает**. Основной поток: надиктовал → вставил из буфера обмена в нужное приложение (письмо, чат, документ). Окно ввода должно появляться по одному действию и сразу принимать фокус и диктовку — без лишних шагов и кликов.

## 3. Сценарии использования (user stories)

Каждый сценарий — с критериями приёмки. Все критерии должны выполняться.

### US-1. Открытие окна по клику на иконку

Как пользователь, я хочу, чтобы **клик по иконке на верхней панели** сразу открывал окно ввода.

Критерии приёмки:
- Клик по иконке → окно ввода открывается немедленно, без промежуточного меню.
- Фокус с самого начала находится в поле ввода (можно печатать без дополнительного клика).
- Повторный клик по иконке при уже открытом окне не создаёт второй экземпляр: фокус возвращается существующему полю, введённый текст сохраняется, окно не закрывается и не затемняется заново.
- Верхняя панель остаётся полностью доступной при открытом окне: её элементы (часы, системные индикаторы, апплеты и значки других расширений — напр., история буфера обмена) кликабельны и работают как обычно; затемнение не перекрывает панель.
- При открытом окне вся панель кликабельна; клик по элементу панели **может увести фокус из поля ввода** (возврат — повторным кликом по иконке). Это осознанный компромисс «панель доступна» (без grab-перехвата).
- Иконка на панели — собственная symbolic-иконка расширения (`icons/voice-input-helper-icon-symbolic.svg`, символ вставки из буфера обмена); её цвет следует за цветом панели (см. US-7).

### US-2. Диктовка текста через Myna

Как пользователь, я хочу надиктовывать текст прямо в окно расширения, чтобы не переключаться между приложениями.

Критерии приёмки:
- Поле ввода — настоящее редактируемое **многострочное** поле с автопереносом строк (технический ориентир — `Clutter.Text`; возможна иная обёртка при сохранении свойств), с корректным фокусом (`global.stage.set_key_focus`), видимое механизмам доступности и Wayland input methods.
- `Enter` и `Shift+Enter` вставляют перевод строки; `Ctrl+Enter` — «Копировать и закрыть» (см. US-3); Enter текст не отправляет и окно не закрывает.
- При активации Myna распознанный текст вводится в поле, как при обычной печати (в т.ч. с переводами строк).
- После вставки распознанного фрагмента фокус остаётся в поле ввода. Диктовка в несколько заходов (пауза и возобновление распознавания) продолжается в то же поле без дополнительных кликов; каждый следующий фрагмент вставляется в позицию курсора.
- Окно остаётся открытым во время и после диктовки.

#### Редактирование текста

Поле ведёт себя как обычное текстовое поле GNOME:
- `Ctrl+A` — выделить всё; `Ctrl+C` / `Ctrl+X` / `Ctrl+V` — копировать / вырезать / вставить.
- Выделение мышью (протяжкой).
- Выделение с клавиатуры: `Shift+←/→` — по символу, `Shift+↑/↓` — по строке, `Ctrl+Shift+←/→` — по словам.
- Выделенный текст копируется, вырезается и удаляется (`Del` / `Backspace`); ввод при выделении заменяет выделенное.

#### Горячие клавиши

| Клавиша | Действие |
|---|---|
| `Enter`, `Shift+Enter` | перевод строки в поле |
| `Ctrl+Enter` | «Копировать и закрыть» (равносильно кнопке «Копировать») |
| `Esc` | закрыть окно (см. US-4) |
| `Ctrl+A` | выделить всё |
| `Ctrl+C` / `Ctrl+X` / `Ctrl+V` | копировать / вырезать / вставить (выделенное, через буфер обмена) |
| `Shift+←/→`, `Shift+↑/↓` | выделение по символу / по строке |
| `Ctrl+Shift+←/→` | выделение по словам |
| `Del`, `Backspace` | удалить выделенное (или символ у курсора) |

### US-3. Копирование текста в буфер и закрытие

Как пользователь, я хочу, чтобы после диктовки текст одним действием ушёл в буфер обмена, а окно закрылось.

Критерии приёмки:
- Кнопка «Копировать» (и `Ctrl+Enter`) копирует всё содержимое поля в буфер обмена, включая переводы строк.
- Окно закрывается сразу, фокус возвращается ранее активному окну.
- Появляется системное уведомление о том, что текст скопирован. *(в v1 — временно, как отладочное; планируется удалить — см. «Бэклог», v1.1.)*
- При пустом поле «Копировать» показывает уведомление «Нечего копировать» и не закрывает окно (см. также раздел 4).

### US-4. Закрытие окна

Как пользователь, я хочу закрывать окно привычным способом — без поиска кнопки.

Критерии приёмки:
- Окно закрывается любым из трёх способов:
  1. кнопка «Закрыть» в окне;
  2. клавиша `Esc`;
  3. клик по затемнённому фону вне окна (верхняя панель «фоном» не является: она остаётся доступной, клики по её элементам работают как обычно, клик по иконке возвращает фокус — см. US-1).
- Если фокус ушёл из окна (например, клик по панели или другому приложению), способы закрытия, связанные с самим окном (клик по фону, `Esc`), не срабатывают, пока фокус не вернётся в окно (повторным кликом по иконке).

### US-5. Сохранение текста между открытиями

Как пользователь, я хочу, чтобы надиктованный текст не пропадал, если я случайно закрыл окно.

Критерии приёмки:
- После закрытия и повторного открытия окна (в пределах активной сессии GNOME Shell) текст остаётся в поле ввода.

### US-6. Очистка поля

Как пользователь, я хочу быстро очистить поле для следующей диктовки.

Критерии приёмки:
- Кнопка «Очистить» стирает содержимое поля.
- Фокус остаётся в поле ввода после очистки (можно диктовать сразу).

### US-7. Внешний вид

Как пользователь, я хочу, чтобы окно выглядело как часть системы и хорошо читалось в любой теме.

Критерии приёмки:
- Окно следует системной теме оформления модальных диалогов GNOME Shell: фон, цвет текста, рамка/скругление и кнопки — как у системных диалогов.
- Читабельность: текст, выделение, курсор и подсказка в пустом поле контрастны и читаются как в светлой, так и в тёмной теме.
- При смене системной темы (светлая ↔ тёмная) оформление переключается корректно, в т.ч. при открытом окне, без перезапуска расширения.
- Окно учитывает системный масштаб шрифта (Универсальный доступ → «Крупный текст»).
- Иконка на панели перекрашивается вместе с панелью (symbolic-иконка).
- Пустое поле показывает подсказку; минимальная высота поля — несколько строк (поле не схлопывается в одну строку).
- Технически: в стилях расширения нет хардкод-цветов — цвета берутся из темы Shell.
- По умолчанию скругление и тень окна — системные; в настройках расширения есть опция «Собственное скругление и тень» (применяется сразу, без перезапуска).

## Бэклог (планируемые итерации)

Перечисленные ниже изменения относятся к будущим итерациям и в v1 не входят.

- **v1.1 — убрать уведомление о копировании.** После подтверждения механики копирования постоянное уведомление «Текст скопирован» необязательно и может отвлекать; в v1 остаётся как отладочное. Уведомление «Нечего копировать» остаётся всегда.
- **v1.2 — глобальная горячая клавиша открытия окна.** Введение потребует настроек и схемы keybinding; рассматривается после v1.
- **v1.3 — настройки расширения.** Преобразовать заготовку `prefs.js` в информационную страницу, затем — под клавишу из v1.2.
- **v1.4 — настройка ширины окна.** В v1 ширина фиксированная (`max-width` в CSS, пиксели). Сделать ширину настраиваемой (через v1.3: prefs.js + GSettings + смена CSS-класса по настройке).
- **v1.5 — вертикальный скролл в окне ввода.** В v1 высота окна «авто» (растёт с текстом; при очень длинном тексте кнопки могут уходить за нижнюю границу экрана — fallback: `Ctrl+A` + Delete). Скролл требует ручного сдвига `Clutter.Text` (обёртка не поддерживает `StScrollable`), рассматривается отдельной UX-итерацией.

## Открытые вопросы

- **Подтверждение многострочного ввода** — автоскролл к курсору и корректный фокус для input methods проверяются эмпирически (devkit) до реализации.
- **Проверка диктовки Myna** — невозможна в devkit-сессии (Myna там недоступна); проводится на основной машине либо в виртуальной машине.
