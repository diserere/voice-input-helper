## Что это за проект

«Voice Input Helper» — расширение GNOME Shell 50 для быстрого голосового ввода текста. Пользователь надиктовывает текст через системное распознавание речи **Myna** (Ubuntu Speech-to-Text) в буферное окно расширения, текст попадает в буфер обмена — и вставляется в нужное приложение. Минимум действий между «хочу сказать» и «текст вставлен».

## Требования — главный артефакт

Единственный полный источник требований — **[REQUIREMENTS.md](REQUIREMENTS.md)** (user stories US-1…US-7 с критериями приёмки: открытие окна по клику на иконку, диктовка через Myna в многострочное поле (с редактированием текста и сохранением фокуса между фрагментами диктовки), копирование в буфер с уведомлением, закрытие Esc/кнопкой/кликом по фону, сохранение текста между открытиями, очистка поля, внешний вид по системной теме). Документ на русском; перед реализацией читать его.

## Команды разработки

Системы сборки, линтера и тестов в репозитории нет.

- **Установка расширения**: `./install.sh` — создаёт симлинк `~/.local/share/gnome-shell/extensions/voice-input-helper@diserere.github.com` → текущий каталог. Если цель уже существует, расширение не переустанавливает. Флаг `-l` выводит список установленных расширений, `-n` — имя (UUID) расширения.
- **Запуск в изолированном окружении GNOME Shell** (devkit): `./run-gnome-shell-devkit.sh` — `dbus-run-session -- gnome-shell --devkit`. Полный лог пишется в `.tmp/devkit.log`, на экран выводятся только строки, совпадающие с `voice-input-helper|diserere\.github\.com|JS ERROR`. Сессия живёт до ручного завершения.
- **Перезапуск расширения**: `./restart-extension.sh` (disable + enable; `-e` / `-d` / `-h`). В основной сессии перечитывает **только CSS** — JS-код кэшируется (ES-модули), для изменений JS нужен перелогин или devkit.
- **QA-процесс и чек-лист**: см. [docs/qa/](docs/qa/) (`PROCESS.md` — как тестировать, `CHECKLIST.md` — чек-лист, `reports/` — отчёты). Строгий порядок: коммит = протестированный код + заполненный отчёт одним коммитом.

## Архитектура

Расширение выполняется в процессе GNOME Shell как ESM-модуль; импорты вида `resource:///org/gnome/shell/...` (API Shell) и `gi://...` (GObject, St, Adw и т.д.).

- [metadata.json](metadata.json) — `uuid` (определяет путь установки и адрес в логах), `shell-version: ["50"]`, имя и версия расширения.
- [extension.js](extension.js) — точка входа: класс-наследник `Extension` с `enable()` / `disable()`; в `enable()` индикатор добавляется в панель через `Main.panel.addToStatusArea(this.uuid, …)`. По ТЗ клик по иконке должен сразу открывать окно ввода (без промежуточного меню), повторный клик — возвращать фокус существующему окну.
- [prefs.js](prefs.js) — наследник `ExtensionPreferences` (`fillPreferencesWindow`), виджеты на Adw; расширение слушает `changed::<ключ>` и применяет настройки на лету.
- [stylesheet.css](stylesheet.css) — геометрия окна; цвета не задаются (тема Shell).

Ключевые решения реализации: поле — `St.Entry` (тема даёт цвета текста/выделения/курсора), внутри многострочный `clutter_text` (`single_line_mode:false`, `activatable:false`, автоперенос); Enter/Shift+Enter вставляют перевод строки явно, `Ctrl+Enter` копирует и закрывает. Фокус — `global.stage.set_key_focus(clutter_text)` строго после `show()` (иначе Myna получает «focus lost»). Окно — в `Main.uiGroup` **без `pushModal`** (grab «глушил» панель), фокус предыдущего актора сохраняется и возвращается вручную; затемнение — подложка по `workArea` (ниже панели), клик по ней закрывает. Буфер — `St.Clipboard`, уведомления — `Main.notify`.

## Особенности окружения разработки

- Система: Ubuntu 26.04, GNOME Shell 50.1 / mutter 50.1. Devkit-сессия поднимается под Wayland с виртуальным монитором (Meta-0) и требует `dbus-run-session`.
- **Myna в devkit-сессии недоступна** — проверить диктовку там нельзя. Проверка — на основной машине либо в виртуальной машине (см. REQUIREMENTS.md, «Открытые вопросы»).
- `./run-gnome-shell-devkit.sh` логирует в `.tmp/devkit.log` (в gitignore); в шапке скрипта — памятка, как искать логи расширения в основной сессии (`journalctl`).
- **Взаимодействие с DING** (`ding@rastersoft.com`): на закрытие любого окна (в т.ч. индикатора Myna) DING активирует верхнее окно приложения и уводит фокус из полей Shell — в расширении есть защита фокуса (`_onKeyFocusChanged`, extension.js).
